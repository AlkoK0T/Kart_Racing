# Архитектура Kart Racing Display

## Общая схема

`run.py` — composition root: участие модуля определяется вызовом
`runtime.add(...)` только в этом файле.

```text
FileSource ──┐
ClockSource ─┼──> DataStore ──> EventBus ──┬──> ScreenDisplay (3 окна)
TcpSource ───┤                             └──> другие подписчики
SerialSource─┘
                     │
                     └──> Flask / HTML / JSON API
```

При `python run.py` запускаются файловый источник, часы, включённые TCP/RS-232/ODTEMP,
три Pygame-окна, а затем Flask. Reloader отключён, чтобы не запускать модули дважды.
При завершении `Runtime.stop()` останавливает их в обратном порядке.

## Ядро

### EventBus

Синхронная потокобезопасная шина поддерживает конкретные topics и wildcard `*`.
Обработчик можно безопасно отписать. Основные события:

- `data.<key>` — изменена конкретная категория;
- `data.changed` — изменились любые данные;
- `data.removed` — категория удалена;
- `display.view` — изменён вариант веб-индикации.

Обработчики исполняются в потоке издателя. Долгие операции должны выполняться во
внутреннем worker модуля либо подписываться с `queued=True, queue_size=64`.
Такая подписка имеет отдельный worker и ограниченную очередь: при переполнении
новое уведомление отбрасывается с WARNING, не блокируя источник; потребитель
актуальных данных может перечитать snapshot. Ошибка callback записывается с
topic/source/handler и не мешает остальным уведомлениям. subscriber_health()
возвращает счётчики сбоев/пропусков и последнее исключение без рекурсивной
публикации события здоровья. Запись считается принятой после store.set независимо
от ошибок наблюдателей. Отписка останавливает worker; bus.close() освобождает
все подписки. Синхронный callback обязан быть коротким, произвольный зависший
Python-код принудительно остановить нельзя.

### DataStore

Потокобезопасное хранилище содержит один `DataValue` на ключ:

```text
value       фактические данные
updated_at  UTC-время записи
source      идентификатор источника
revision    монотонный номер изменения
quality     good / stale / unavailable (по умолчанию good)
```

Новый снимок атомарно заменяет старый, поэтому объём памяти не растёт со временем.
Историю при необходимости следует реализовать отдельным подписчиком, например на
SQLite. Всем модулям доступен полный `snapshot()`.

Запись и все чтения используют defensive deepcopy. Объекты входа, get/item,
snapshot и payload отдельного подписчика не являются ссылками на внутренние
данные. Изменения выполняются только через API store. Значения должны поддерживать
deepcopy; ошибка копирования входа возникает до записи. snapshot_with_revision()
атомарно возвращает отсоединённые DataValue всех категорий и общую ревизию.

### Runtime

Модули запускаются в порядке добавления. Если запуск очередного модуля завершается
ошибкой, уже запущенные модули останавливаются в обратном порядке. Штатная остановка
также идёт в обратном порядке.

Очистка включает модуль с частичным start и продолжает работу после ошибки
отдельного stop. Ошибки остановки агрегируются, первичная ошибка запуска сохраняется.
Повторный start работающего runtime и повторный stop безопасны; новый запуск после
неуспешной очистки запрещён до успешного stop. add(module, required=False) разрешает
отказ необязательного модуля с состоянием degraded; по умолчанию модуль обязателен.
Supervisor проверяет жизнь worker, а /api/health показывает health_snapshot runtime.
Модули не создают второй живой поток и не сообщают stopped, если join не завершился.

## Модель данных

| Ключ | Назначение |
|---|---|
| `current_race` | гонка, участники, круги и вычисленные показатели |
| `records_day` | рекорды дня: `children`, `women`, `men` |
| `records_month` | рекорды месяца по тем же категориям |
| `current_time` | timezone-aware локальное время |
| `temperature` | температура |
| `forecast_tomorrow` | прогноз на завтра |

Внутренний API DataStore остаётся открытым. Для внешних данных новые категории
добавляются явной регистрацией валидатора в общем DataIngestor без изменения ядра.

### Валидация внешних данных

FileSource, TcpJsonSource и SerialSource используют общий DataIngestor, созданный
в run.py. karting/ingestion.py содержит реестр категорий и разбор UTF-8 JSON/YAML;
karting/domain.py — проверку снимков и чистый расчёт показателей гонки.

JSON проверяется по interface.md. Старый YAML имеет отдельный режим совместимости:
целочисленные номера карт, короткие рекорды и универсальные таблицы поддерживаются.
Версионированный YAML использует контрактную структуру. Проверяются обязательные
поля, допустимые значения, конечность чисел и лимиты входа/коллекций. Ошибка
валидации происходит до store.set и не меняет данные, ревизию или события.

Это граница внешнего ввода, не изменение семантики EventBus/DataStore. Часы и
ODTEMP пока используют внутренний API напрямую; их отдельные замечания ревью
не исправляются CR-03.

## Источники

### FileSource

Раз в `FILE_POLL_INTERVAL` секунд выбирает максимальный `mtime` в каждом
`data/<category>/*.yaml`. Неизменённый файл не создаёт ревизию, а ошибка чтения или
YAML не затирает корректный снимок.

YAML в корне `data/` временно трактуется как `current_race`. Формат `laps`
нормализуется для старых Flask-шаблонов: рассчитываются позиции, лучшие, последние
и средние круги, дельты и суммарное время.

### TcpJsonSource

Многопоточный JSON Lines сервер. Сообщение имеет поля `category` и `data`, лимит
строки — 1 МиБ. В одном соединении допустимо несколько сообщений. Ответ также JSON.

### SerialSource

Открывает `SERIAL_PORT` через pyserial. Принимает полный JSON либо одно число
температуры. Пустые и неизвестные строки игнорируются. Без порта модуль не создаётся.

### ClockSource

Раз в секунду записывает локальный `datetime` в `current_time`.

### ODTempSource

Ищет USB CDC порт по VID:PID `0483:A26A` через `serial.tools.list_ports`. Команда
`~I` сохраняет идентификацию, `~F` читает период автоматической выдачи. Если выдача
выключена, отправляется `~W<период>`. После этого модуль не опрашивает датчик, а
пассивно принимает `~G...`, обновляя `temperature` и при наличии `humidity`.

Watchdog измерений равен 120 секундам. При таймауте или ошибке USB порт закрывается,
`odtemp_device` удаляется, затем раз в 60 секунд повторяются автоопределение и полная
инициализация до успеха. Явный `ODTEMP_PORT` имеет приоритет над поиском.

Recovery считается завершённым не после открытия COM-порта, а после первого
корректного сообщения `~G`. Переходы состояния (`connection lost`, попытка
автодетекта, инициализация и `temperature reading restored`) журналируются на INFO.

При watchdog/потере связи показания с владельцем odtemp помечаются stale/unavailable;
последнее значение и время измерения сохраняются для диагностики. Новая запись
возвращает quality=good. Отсутствие влажности в новом измерении делает прежнюю
влажность odtemp недоступной. Другой производитель не затрагивается: проверка
владельца выполняется атомарно под lock store. Экран скрывает неактуальную
температуру; /api/data возвращает null для неактуальных датчиков. /api/health
показывает качество, last_value, received_at, источник, статусы модулей и подписчиков.

## Flask

Фабрика `create_app(runtime)` сохраняет runtime в `app.extensions`. Маршруты не
читают исходные файлы напрямую. HTML получает `current_race` из `DataStore`,
`/api/data` возвращает полный снимок, а `/check-updates` использует ревизии и
condition variable для long polling.

Condition принадлежит store и использует его lock. wait_for_revision повторно
проверяет predicate до deadline, включая ложные пробуждения. Глобальная revision
монотонна при set, изменении качества и remove существующей категории. Ревизия
категории сохраняется после удаления как tombstone; category_snapshot атомарно
читает снимок и эту ревизию. data.changed содержит operation и revision.
Подвид style1/style2 принадлежит конкретному Flask-приложению. Глобальных
Condition, списка id runtime и ленивых подписок больше нет.

## Pygame-индикация

### Lifecycle

`ScreenDisplay` требует ровно три `ScreenConfig` и запускает один SDL2/Pygame event
loop в собственном потоке. Для каждого экрана создаются:

- независимый `pygame._sdl2.video.Window`;
- отдельный аппаратный `Renderer`;
- streaming `Texture` размером с окно;
- `pygame.Surface` для композиции.

Окна имеют собственные координаты и разрешения. `start()` ждёт их инициализации до
пяти секунд. Ошибка окна или renderer передаётся в `Runtime`, который выполняет
откат ранее запущенных модулей.

### Планирование и кадр

`ContentPlanner` не зависит от GUI. По конфигурации, данным и прошедшему времени он
возвращает `ScreenFrame` с верхними/нижними строками, эффектом и GIF-фоном.

Для стандартного окна 320×160:

- верхние 320×80: время/температура либо рекорд дня выбранной категории;
- нижние 320×80: очередное настраиваемое сообщение.

На каждом кадре Pygame выбирает страницы и GIF-кадр, собирает фон, разделитель и
текст на Surface, обновляет streaming texture и вызывает `Renderer.present()`.
Шрифты кэшируются. FPS и интервалы задаются на уровне экрана.

### GIF

Pillow декодирует GIF в RGBA и один раз масштабирует кадры до верхней половины.
Pygame Surface хранятся в кэше `(path, width, height)`.

```yaml
background_time_temperature: "assets/time-temperature.gif"
background_daily_record: "assets/daily-record.gif"
```

`previous` разрешается в путь соседнего вида. Оба используют общий кэш и абсолютное
прошедшее время, поэтому анимация не сбрасывается. Отсутствующий или повреждённый
GIF заменяется процедурным эффектом `waves` либо `pulse`.

## Конфигурация

| Группа | Переменные |
|---|---|
| Flask | `PORT`, `DEBUG`, `SECRET_KEY` |
| Файлы | `DATA_FOLDER`, `FILE_POLL_INTERVAL` |
| TCP | `TCP_ENABLED`, `TCP_HOST`, `TCP_PORT` |
| RS-232 | `SERIAL_PORT`, `SERIAL_BAUDRATE` |
| ODTEMP | `ODTEMP_ENABLED`, `ODTEMP_PORT`, `ODTEMP_VID`, `ODTEMP_PID`, `ODTEMP_STREAM_INTERVAL_MS`, `ODTEMP_WATCHDOG_TIMEOUT`, `ODTEMP_RECONNECT_INTERVAL` |
| Экраны | `DISPLAY_ENABLED`, `DISPLAY_CONFIG` |
| Журнал | `LOG_LEVEL`, `LOG_FILE`, `LOG_MAX_BYTES`, `LOG_BACKUP_COUNT` |

`DISPLAY_ENABLED=True` по умолчанию, поэтому `run.py` запускает web и окна вместе.
Для headless-режима используется `DISPLAY_ENABLED=False`.

## Журналирование

`configure_logging()` настраивает общий root logger до создания runtime. Один формат
содержит время, уровень, поток, logger и сообщение. Вывод идёт в консоль и
`RotatingFileHandler`; размер и число архивов конфигурируются.

`EventBus` на DEBUG журналирует каждую публикацию (`topic`, `source`, `payload` и
число обработчиков), а `DataStore` — ключ, источник, ревизию и значение. Источники
добавляют исходные строки и конкретный transport/file/port. ScreenDisplay пишет
сформированный `ScreenFrame`. INFO предназначен для lifecycle и рабочих переходов,
WARNING/ERROR — для повреждённых данных, таймаутов и отказов. Стандартный access-log
Werkzeug подавлен до WARNING, поскольку HTTP-детали уже доступны на DEBUG.

## Тестирование

- `core.feature` — события, хранилище и lifecycle;
- `files.feature` — категории, выбор файлов и ошибки YAML;
- `sources.feature` — часы, TCP, имитация RS-232 и протокол ODTEMP;
- `web.feature` — HTML/API и состояние;
- `screens.feature` — конфигурация, рекорды, GIF и Pygame Surface.
- `com_inventory.feature` — стабильные ID, MOVED/ABSENT и пополнение CSV.

TCP использует свободный порт, RS-232 подменяется программным объектом, а кадр
Pygame проверяется в памяти. validation.feature проверяет отказы контрактного
ввода, сохранение снимка и регистрацию расширений. Текущий результат: 67 сценариев,
291 Behave-шаг и 57 unit-тестов; отдельно проверяется test_tcp_race_contract.py.

## Независимая инвентаризация COM

`com_port_inventory.py` работает отдельно от runtime и только читает сведения ОС.
USB-устройство с серийным номером получает ID `USB:<VID>:<PID>:<serial>`; для
остальных используется SHA-256 digest полного HWID. Реестр `com_devices.csv`
связывает ID с понятным именем и ожидаемым портом. Сравнение выдаёт `OK`, `MOVED`,
`NEW` или `ABSENT`; неизвестные строки добавляются только по `--add-new`.

## Расширение

Новый источник получает `DataStore`, реализует `start()/stop()` и добавляется в
`build_runtime()`. Новый модуль индикации может подписаться на события и читать
любой ключ общего хранилища; изменять существующие источники не требуется.
