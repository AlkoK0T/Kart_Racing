# Интерфейс передачи данных в Kart Racing Display

Версия контракта: **1.0**.

Статус: контракт реализован для `current_race`, `records_day` и `records_month`.

Документ предназначен для приложения, передающего состояние гонки и статистику
картинг-центра. Транспорт — TCP с сообщениями JSON Lines.

## 1. Подключение

```text
host: 127.0.0.1
port: 8765
transport: TCP/IPv4
encoding: UTF-8
framing: один JSON-объект на строку, окончание LF (0A)
maximum line size: 1 MiB
```

Для удалённого отправителя на принимающей стороне задайте `TCP_HOST=0.0.0.0` либо
конкретный локальный адрес и разрешите порт 8765 в межсетевом экране.

Соединение можно создавать для каждого сообщения или держать открытым. На каждую
входную строку сервер возвращает одну строку ответа.

## 2. Общий конверт

```json
{"category":"records_day","data":{"children":null,"women":null,"men":null}}
```

| Поле | Тип | Обязательно | Назначение |
|---|---|---:|---|
| `category` | string | да | категория данных |
| `data` | object | да | полный актуальный снимок категории |

Категории контракта:

- `current_race` — текущая гонка;
- `records_day` — рекорды текущего дня;
- `records_month` — рекорды месяца, необязательно.

Новый снимок целиком заменяет предыдущий снимок категории. Дельты не передаются.

## 3. Ответ сервера

Успех:

```json
{"ok":true}
```

Ошибка:

```json
{"ok":false,"error":"data.children: is required; use null for an absent record","field":"data.children"}
```

Сообщение считается доставленным только после `"ok":true`. После сетевой ошибки
полный снимок можно повторить — операция идемпотентна.

При ошибке валидации предыдущий снимок, его ревизия и события обновления не
изменяются. `field` указывает проблемное поле, `error` — причину. Исправленное
сообщение можно отправить в том же соединении. Превышение лимита строки приводит
к ответу с ошибкой и закрытию соединения. Поле `field` предназначено для
диагностики, не для привязки клиента к точному английскому тексту ошибки.

## 4. Текущая гонка

Категория: `current_race`.

### 4.1 Входной снимок гонки

```json
{
  "category": "current_race",
  "data": {
    "schema_version": 1,
    "race_id": "2026-10-08-0042",
    "state": "running",
    "started_at": "2026-10-08T18:42:15+01:00",
    "updated_at": "2026-10-08T18:47:31+01:00",
    "participants": {
      "7": {"name": "Иван Петров", "category": "men"},
      "12": {"name": "Анна Смирнова", "category": "women"}
    },
    "laps": {
      "7": [31.842, 30.991, 30.715],
      "12": [33.120, 31.880]
    }
  }
}
```

### 4.2 Поля

| Поле | Тип | Обязательно | Описание |
|---|---|---:|---|
| `schema_version` | integer | рекомендуется | сейчас `1` |
| `race_id` | string | да | стабильный ID гонки |
| `state` | string | да | `waiting`, `running`, `paused`, `finished` |
| `started_at` | string/null | рекомендуется | ISO 8601 с часовым поясом |
| `updated_at` | string | рекомендуется | время снимка ISO 8601 |
| `participants` | object | да | участники по номеру карта/транспондера |
| `laps` | object | да | массив времени кругов по тем же ключам |
| `style` | string | нет | `laps` по умолчанию или `race` |

Ключи `participants` и `laps` должны совпадать. JSON-ключ является строкой. Время
круга — число секунд с точкой. Аннулированный круг не включается. Категория
участника: `children`, `women` или `men`.

Имя участника обязательно и непустое. Время завершённого круга строго больше
нуля и конечно; строки, boolean, `NaN` и `Infinity` не принимаются. Для участника
без завершённых кругов передавайте `[]`.

Принимающая программа рассчитывает лучший, последний и средний круг, число кругов,
суммарное время, позиции и дельты. Отправитель передаёт только исходные круги.

### 4.3 Частота обновлений

Полный снимок следует отправлять:

- при старте и каждой смене `state`;
- после регистрации нового круга;
- после изменения участника или удаления ошибочного круга;
- при завершении со `state="finished"`.

Одинаковый снимок не нужно отправлять чаще одного раза в секунду. Между гонками
можно оставить последний `finished` либо отправить:

```json
{"category":"current_race","data":{"schema_version":1,"race_id":"next","state":"waiting","participants":{},"laps":{}}}
```

## 5. Дневная статистика

Категория: `records_day`.

Минимум — полный снимок после каждой гонки. Его также отправляют после ручной
коррекции; во время гонки обновление допустимо, если рекорд засчитывается сразу.

```json
{
  "category": "records_day",
  "data": {
    "schema_version": 1,
    "date": "2026-10-08",
    "updated_at": "2026-10-08T18:48:02+01:00",
    "children": {
      "name": "Мария Иванова",
      "time": 31.2,
      "kart": "7",
      "race_id": "2026-10-08-0038",
      "achieved_at": "2026-10-08T16:15:03+01:00"
    },
    "women": {
      "name": "Анна Смирнова",
      "time": 29.8,
      "kart": "12",
      "race_id": "2026-10-08-0042",
      "achieved_at": "2026-10-08T18:46:11+01:00"
    },
    "men": {
      "name": "Иван Петров",
      "time": 28.4,
      "kart": "3",
      "race_id": "2026-10-08-0040",
      "achieved_at": "2026-10-08T17:32:40+01:00"
    }
  }
}
```

Поля каждой категории:

| Поле | Тип | Обязательно | Описание |
|---|---|---:|---|
| `name` | string | да | имя для индикации |
| `time` | number | да | рекорд круга в секундах |
| `kart` | string | рекомендуется | номер карта |
| `race_id` | string | рекомендуется | ID гонки |
| `achieved_at` | string | рекомендуется | ISO 8601 |

Если результата нет, передаётся `null`. Всегда передавайте все три ключа, чтобы не
оставлять устаревшие записи:

```json
{"children":null,"women":null,"men":null}
```

## 6. Месячная статистика

`date` и `month` необязательны для совместимости с существующими отправителями.
Если присутствуют, должны быть реальной датой `YYYY-MM-DD` и месяцем `YYYY-MM`
соответственно. `month` в дневном снимке и `date` в месячном запрещены.
Это проверка формата периода; политика актуальности и смены периода — отдельная
задача CR-14. Время рекорда должно быть конечным числом строго больше нуля.

`records_month` имеет ту же структуру. Вместо `date` используется `month`:

```json
{"category":"records_month","data":{"schema_version":1,"month":"2026-10","children":null,"women":null,"men":{"name":"Иван Петров","time":27.9,"kart":"3"}}}
```

## 7. Порядок и повторная отправка

Сервер применяет сообщения в порядке получения; `updated_at` информационный. Лучше
использовать одно соединение или не допускать отправки старого снимка после нового.

Рекомендуемый алгоритм:

1. сформировать полный снимок;
2. сериализовать UTF-8 без `NaN` и `Infinity`;
3. добавить LF;
4. отправить;
5. дождаться ответа;
6. при `ok=true` зафиксировать доставку;
7. при ошибке повторить с задержкой, сохраняя только новейший снимок категории.

## 8. Типы данных

- кодировка строго UTF-8;
- дробная часть отделяется точкой: `30.715`;
- время круга является числом, не строкой;
- даты и время записываются в ISO 8601;
- неизвестное значение — `null`, не `0` и не пустая строка;
- кириллица разрешена;
- строка завершается LF; CRLF также принимается.

Повторяющиеся ключи JSON запрещены. Если `schema_version` присутствует, допускается
только целое `1` (не строка и не boolean). Временные метки, если переданы, должны
содержать часовой пояс; `started_at` также допускает `null`.

Лимиты по умолчанию: вход и оценочный размер развёрнутого снимка — 1 МиБ,
глубина — 32, число узлов — 100000, элементов коллекции — 10000, длина строки —
4096 символов. В гонке не более 128 участников, 2000 кругов у одного участника
и 20000 кругов суммарно. Номер карта — непустая строка до 64 символов;
имя, ID гонки и строковые поля рекорда — до 256 символов.

Стандартный реестр дополнительно содержит `temperature`, `humidity`,
`current_time` и `forecast_tomorrow`. Новую категорию необходимо явно
зарегистрировать на принимающей стороне. Укороченные старые YAML-файлы
обрабатываются отдельным адаптером совместимости и не ослабляют JSON-контракт.

## 9. Диагностика

Принятое состояние:

```text
GET http://127.0.0.1:5000/api/data
```

Входные TCP-сообщения и значения доступны в `karting.log` при `LOG_LEVEL=DEBUG`.

## 10. Delphi 7

`delphi/KartRecordsSender.pas` уже реализует передачу `records_day` и
`records_month`, UTF-8, JSON Lines и проверку ответа:

Важно: Delphi-отправитель пока требует исправления CR-19 для отсутствующих
результатов. Не отправляйте фиктивную запись с временем `0`: сервер отклонит её;
по контракту требуется `null`. Компиляция Delphi 7 в рамках CR-03 не проверялась.

```pascal
SendDayRecords('127.0.0.1', 8765,
  ChildrenRecord, WomenRecord, MenRecord, Response, ErrorText);
```

Для текущей гонки применяется тот же конверт с `category="current_race"`.
